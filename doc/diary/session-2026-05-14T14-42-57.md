# Session diary — 2026-05-14 (local)

## Goal

Wire up the software rasterizer binary so it exports a lossless WebP still of a **wireframe cube** (edge length **0.5** in world units), using existing **`FrameBuffer`** line drawing and **`ortho_projection::project`**, then fix apparent **aspect distortion** and **commit** the result.

## Work completed

### Cube wireframe in `main`

- Replaced the earlier radial “flower” demo with a **unit-grid cube** in world space: half-extent **0.25**, **8** corners **`const CUBE_VERTS`**, **12** edges **`const CUBE_EDGES`**.
- Each edge: `project(vertex, SCENE_WIDTH, SCENE_HEIGHT)` → `framebuffer::Point` → `draw_line`.
- **Rotation:** **`Mat3::from_rotation_x(tilt) * Mat3::from_rotation_y(tilt)`** with **`tilt = FRAC_PI_4`**, applied to all corners before projection. Rationale documented in code: **`project` only uses `x` and `y`** ( **`z` ignored** ), so without tilt, an axis-aligned cube collapses to one square and “vertical” (depth-only) edges disappear on screen.

### Temporary axis-aligned pass

- Rotation was removed briefly so the viewport showed a **single face-on square** (expected given **z**-agnostic projection), to compare width vs height on a simple shape.

### Orthographic projection: aspect-correct mapping (`src/ortho_projection.rs`)

- **Problem:** Original `project` mapped **`[-1, 1]` × `[-1, 1]`** independently to the full **`width × height`** pixel span. On **800×600**, a world **square** became a **4:3 rectangle** on the bitmap.
- **Fix:** Single scale **`scale = min(width − 1, height − 1) / 2`**, centered:
  - `px = world.x * scale + (width − 1) / 2`
  - `py = -world.y * scale + (height − 1) / 2`
- **Effect:** **Letterboxing / pillarboxing** on the long axis; world squares stay **square** in pixels.
- **Edge case:** **`width == 0` or `height == 0`** → return **`UVec2::ZERO`**.
- **Tests:** Updated corner expectations for **101×51**; added **`square_viewport_corners_touch_frame_edges`** ( **`n×n`** still hits edges ) and **`non_square_viewport_preserves_equal_axis_span_in_pixels`** (**800×600** equal pixel span for **2** world units along **x** vs **y**).
- **Docs:** Module comment updated to describe aspect behavior.

### Design note (discussion only)

- Confirmed that deriving the same mapping via **`width/height`** (choosing the limiting dimension, or equivalently squeezing one axis) matches the **`min(width, height)`** formulation—same pixel density on **x** and **y**, centered.
