## Concept: “three-axis Euler sweep” (early thread)

- **Euler angles:** orientation as three successive rotations about axes (with a fixed order).
- **Sweep:** advance those angles **over the animation** so motion exercises **X, Y, and Z** (not a single-axis spin).
- **Project note:** a **single angle** `t` for all three avoids frequency mismatch and keeps a **seamless loop** when each factor completes whole turns at `t = τ`.

## Implementation trajectory

### 1. Euler tumble in code

- **Motion:** `R_z(t) * R_y(t) * R_x(t)` with `t = (frame_index / lap_frames) * τ` (column-vector convention: **X** then **Y** then **Z** on the vector when read right-to-left through the product).
- **Initial placement:** `model_matrix_euler_sweep` lived in **`wireframe.rs`** and composed with **`model_matrix_still()`** (tilt + scale).

### 2. Animation pose without still tilt

- User request: **do not** use **`model_matrix_still`** for the animation—**only** **0.5** uniform scale on the unit cube.
- **Effect:** orthographic **axis-aligned** moments can **collapse** depth edges on screen; acceptable tradeoff; still uses tilt for **readability** in the single-frame snapshot.

### 3. Move transforms beside each binary

- **`src/bin/still-cube.rs`:** private **`model_matrix_still()`**, **`TILT = π/4`**, **`glam`** **`Mat3`/`Mat4`/`Vec3`**.
- **`src/bin/animated-cube.rs`:** private **`model_matrix_euler_sweep`**, same **`glam`** imports.
- **`src/wireframe.rs`:** **`draw_edges` only**; module doc updated.

### 4. Planning document

- **Animation milestone** (`[x]`): documents **shipped** Euler tumble, **scale-only** animated mesh, tilt **only** on **`still-cube`**, **`wireframe`** = **`draw_edges`**.
- **Perspective milestone:** outcome bullet now says **same frame count, timing, and Euler tumble policy** (not legacy “Y-only” wording).
