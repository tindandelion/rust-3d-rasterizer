## 3. `WebpEncoder` refactor (`src/webp_encoder.rs`)

- Encapsulate **`webp_animation::Encoder`** in **`WebpEncoder`**:
  - **`new(width, height)`**
  - **`add_frame(rgba: &[u8])`** — pixel data required; API cannot be zero-arg.
  - **`write(out_path: impl AsRef<Path>)`**
- **`next_timestamp_ms`** field: underlying encoder requires **strictly increasing** timestamps (`timestamp > previous`). Counter assigns **0, 1, 2, …** ms; **`write`** calls **`finalize(self.next_timestamp_ms.max(1))`** so a single frame still gets a valid end timestamp.
- Brief experiment: drop counter, always **`add_frame(..., 0)`** + **`finalize(1)`** → only one frame possible → **rolled back** per user request.

---

## 4. Q&A — why `i32` for timestamps?

- Matches **`webp_animation`** / **libwebp** (`add_frame` / `finalize` take **`i32`**).
- Internal sentinel **`previous_timestamp == -1`** means “no frames yet.”
- App logic keeps timestamps non-negative with **`saturating_add`**.

## 5. Integration test (`tests/binary_writes_valid_webp.rs`)

- **Goal:** Run the **real binary**, assert output is **decodable WebP**.
- **`tempfile`** dev-dependency; spawn binary with **`current_dir`** = temp dir (no repo pollution).
- Read bytes → **`webp_animation::Decoder::new`** (failure = invalid WebP).
- Assertions: canvas **800×600**, **one** frame, **RGBA**, **`w×h×4`** bytes, center pixel **`[0,0,0,255]`**.
- **Finding binary:** Prefer Cargo’s **`CARGO_BIN_EXE_<target>`**. Built key from **`CARGO_PKG_NAME`** instead of hard-coding `rust-3d-rasterizer`.
- **Cargo 1.95 observation:** env var is **`CARGO_BIN_EXE_rust-3d-rasterizer`** (hyphens preserved), not **`…_rust_3d_rasterizer`**. Underscore-only key caused lookup failure.
- User requested **removing filesystem fallback** (`current_exe` → `target/debug/…`). Test now **requires** **`cargo test`** so **`CARGO_BIN_EXE_*`** is set.
